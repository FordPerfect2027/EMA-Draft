# EMA-Draft・履歴取得中のブロック変更検査

実施日：2026年10月21日（日本時間）

## 今回の修正

前回は履歴内の識別情報を検査しましたが、履歴取得中にチェーンが変わった場合の照合が残っていました。今回は取得開始時に指定範囲の終了ブロックを読み、ハッシュを保持します。

- 戻された各履歴のブロックハッシュを、同じ高さのRPCヘッダーと照合します。
- 同じ高さの照会は重複させず、並列で大量の照会を発生させません。
- 履歴が空でも、終了ブロックを再取得し、開始時のハッシュから変わっていないことを確認します。
- 読み取り中にネットワークが変わった場合も失敗にします。
- 既存承認額は、終了ブロックのハッシュと `requireCanonical: true` を指定して読み取ります。ハッシュ指定が利用できない場合、番号や最新ブロックへ切り替えません。
- `toBlockHash`、`logBlockHashesChecked: true`、`endBlockRechecked: true` を結果へ追加しました。

承認額のハッシュ指定は[EIP-1898](https://eips.ethereum.org/EIPS/eip-1898)を使用します。固定済みviem 2.56.6の実装を確認し、結合検査では実際の `eth_call` の引数にもハッシュと正規チェーン要求が入ることを確認しています。

## 実行した検証

- 読み取り検査：120件。今回追加した29件を含みます。
- ローカル模擬EVMの履歴結合検査：10件。従来の7件に、新しいブロックの追加、Transfer取得中の巻き戻し・置換、Approval取得中の巻き戻し・置換を追加しました。
- 新しい承認が途中で発生しても、結果は指定した元のブロックの承認額7を保持し、最新の承認額11と混同しません。
- 実際に模擬チェーンを巻き戻して同じ高さのブロックを置き換えると検査を拒否し、再取得では置換後の値11を取得できます。
- 空の履歴、欠けたヘッダー、誤った高さ、古い履歴ハッシュ、取得中のネットワーク変更、ハッシュ指定非対応も検査します。
- コンパイル・契約検査・型検査を含む `npm run check` と、既存のWallet結合検査をCIで継続します。

模擬EVMではこのリポジトリの実際の契約ソースを使用します。公開契約アドレスは検査用アダプターでローカル配置先へ対応付けます。実際のBaseネットワークの検査ではありません。チェーンの更新・巻き戻しはテスト用の処理だけが行い、履歴リーダーには読み取りメソッドのみを渡しています。

同じケースをHardhat・独立テスト・複数CIで再実行するため、件数を単純合算して固有のテスト数とは扱いません。

## 互換性と再実行

独自の読み取りアダプターには、追加で `getBlock({ blockNumber, includeTransactions: false })` が必要です。戻り値には指定した高さのbigint型 `number` と32バイトの `hash` が必要です。承認額の `readContract` は `blockHash` と `requireCanonical` を正しく扱う必要があります。

```sh
npm ci
npm run check
```

履歴の結合検査だけの場合は、`npm run compile` の後に `npm run test:history` を実行します。

追加のヘッダー照会数は、返された履歴の異なる高さの数に応じます。既存の件数制限により、送金は最大1000、承認は最大500の履歴ブロックまでです。同じ高さは1回だけ照会し、開始・終了時の終了ブロック照合を加えます。

## 未検証・残る制約

- ヘッダー照合は同じRPCの応答に基づく確認です。独立した正規チェーン証明ではなく、`canonicalityVerified: false` を維持します。
- 範囲指定の履歴取得でRPCが一部の履歴を省略することや、検査中に別のチェーンへ移って元へ戻る一時的な再編成を完全には検出しません。`historyComplete: false` を維持します。取得後の再編成も防ぐものではありません。
- 本番RPC各社のハッシュ指定への対応、実Wallet拡張、外部dAppのログイン完了、独立した安全性監査は未検証です。

- 実Walletでの署名・売買・送金・承認・LP追加、ゲーム開発は行っていません。Solidity契約・本番配備記録・供給量設定も変更していません。
