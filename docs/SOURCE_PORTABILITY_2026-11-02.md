# Deterministic contract source bytes — November 2, 2026

Solidity metadata contains source hashes. Changing CRLF to LF can therefore
change the bytecode metadata even when contract logic stays identical. DAT's
historical verifier exposed this difference against its recorded deployment.

The contracts directory now has a narrow Git LF checkout policy. This change
normalizes the existing EMACore.sol line endings only; it changes no Solidity
statement, compiler setting, dependency, deployment record or expected hash.
It does change the generated bytecode metadata and artifact fingerprint. Rebuild
and review the new artifact rather than labelling it byte-identical to the old one.

The compile command first checks that all Solidity sources use UTF-8 without
BOM and contain no CR. It fails before starting Hardhat if they do not, leaving
the source untouched. The check uses local files only. The source regression
creates isolated Git repositories and checks actual source bytes after checkout
with both autocrlf settings, and verifies CRLF/BOM/invalid-UTF-8 rejection.

Run npm run test:source followed by npm run compile. The ordinary npm run check
also includes the source regression. Existing clones with converted files must
save the contracts using LF before building; no automatic source rewrite occurs
during compilation. Source hashes and fresh-build comparisons are recorded in
the Wallet evidence collection. No live deployment is updated by this change.

## Test routing correction

The legacy Hardhat command recursively discovered every JavaScript/TypeScript
file under test, including the CLI-only preload in test/support. A complete DAT
attempt produced 288 passing cases and one failure because that preload correctly
refused to run without its test-owned loopback configuration. It also repeated
the 251 read-only cases already assigned to test:read-only.

The test command now enumerates all top-level TypeScript specs for Hardhat;
operational *.test.mjs cases remain in test:read-only, and both groups remain in
npm run check. Support files are loaded only by their owning fixtures. The runner
passes through Hardhat arguments and failure status, rejects an empty suite, and
checks source encoding before Hardhat can implicitly compile. Routing regression
tests exercise the real runner with a fixture child command. No test assertion
was removed or relaxed. New nested TypeScript suites would need an explicit
runner policy update rather than silently entering this top-level suite.

The read-only command explicitly uses one test file at a time, matching the
previous complete passing runs and avoiding test-process startup contention.
The request deadlines, assertion coverage and child watchdogs are unchanged.
