# EMA-Draft・Walletのブロック一貫性検証

実施日：2026年10月21日（日本時間）

## 完成した変更

WalletのdApp事前検査で、コード・残高・既存承認額の読み取りを同じブロックハッシュに固定しました。読み取り終了時に、その高さのブロックハッシュが変わっていないことも確認します。

このリポジトリのCIでは、Walletの固定版 `798ac528c3908989c13cf23f30c06349af620e0b` を使用します。トークンのSolidityソースや本番配備記録は変更していません。

## ローカル結合検証

**22件成功、失敗・スキップ0件。** ローカル模擬EVMでチェーンID 8453・84532を使い、それぞれ11件を確認しました。実際のBaseネットワークへの接続ではありません。

- 従来の残高・桁数・最大承認額・誤ったチェーン・アカウント分離など18件を維持。
- 検査途中で模擬送金と承認額変更を行っても、結果は元のブロックの残高・承認額を保持。
- 検査途中で模擬チェーンを巻き戻してブロックを置換すると検査を拒否。新しい検査では置換後の承認額を正しく取得。

模擬チェーン上の配置・送金・承認・焼却はテスト用アカウントだけで行います。Wallet経由では非読み取り要求を拒否します。実Walletでの署名・売買・送金・承認・LP追加は行っていません。

## 再実行

Node 22以降を用い、トークンのディレクトリから実行します。Walletは上記の固定版を使用し、パスを実際の配置に合わせます。

```sh
npm ci
npm run check
node --test ../ThreeCore-Wallet/integration/token-compatibility.test.mjs
```

CIは既存のコンパイル・コントラクト検査・型検査・読み取り検査に加え、この結合検証を実行します。

## 未検証・制約

- 実際のWallet拡張や読み取りサービスのブロックハッシュ指定対応は未検証です。非対応の場合、最新時点の読み取りへ自動的に切り替えず、検査を失敗として扱います。
- 読み取りサービスが正確な応答を返すことが前提です。結果取得後のブロック変更まで防ぐものではありません。
- 単独の残高参照は、ハッシュを明示しなければ従来どおり最新時点を読み取ります。自動固定するのはdApp事前検査です。
